# 현재 법령 데이터의 RAG 검색

기존 `data/regulations/raw/*.json`의 **17개 문서·50개 조항**을 `data/regulations/processed/rag-index.json`으로 변환했습니다. 앱의 텍스트·URL 분석이 이 인덱스를 사용합니다. 기존에 구현된 6개 분류의 데이터를 그대로 포함하며 새 규제 분야를 추가하지 않았습니다.

현재 실행 모드는 **외부 호출 없는 BM25 검색**입니다. OpenAI와 로컬 Ollama 임베딩 연결 코드를 포함하지만, 실제 모델이 설정되지 않은 기본 인덱스에는 벡터가 없습니다. 생성형 LLM 연결은 별도이며, 기존 규칙·템플릿 기반 분석 제공자를 유지합니다.

## 처리 흐름

원본 JSON → 스키마·중복 ID 검사 → 기존 조항 구조로 분리 → 본문·출처 해시 생성 → 선택적 임베딩 → 인덱스 파일 저장

광고 입력 → 기존 주장 추출·분류 → 분류·시행일 필터 → BM25와 선택적 벡터 검색 → 상위 5개 조항 → 기존 분석 제공자 → 주장별 인용 검증 → 검사 결과

- 법령명, 기관, 출처 종류, 시행일, 문서 버전, 조·항·호, 원문과 출처 URL을 보존합니다. 검색용 정규화나 한국어 2글자 단위 분리는 인용 원문을 바꾸지 않습니다.
- 문서 전체와 조항별 SHA-256으로 원본과 인덱스의 일치를 확인합니다. `prebuild`가 이 검사를 실행하여 오래된 인덱스를 빌드하지 않도록 합니다.
- 임베딩 모드에서는 코사인 유사도로 검색하고, BM25와 RRF로 순위를 합칩니다. 기본 벡터 최소 점수 0.3은 초기 검색 설정이며 법적 판단의 확률이 아닙니다. 실제 모델 평가 후 조정해야 합니다.
- 설정한 임베딩이 실패하거나 모델·차원·본문이 인덱스와 다르면 오류로 종료합니다. 검색 실패를 정상 검사 결과로 바꾸지 않습니다.
- 모델이 반환한 인용은 해당 주장에 실제로 검색된 조항 ID, 분류, 시행일, 저장된 조 번호와 대조합니다. 근거 없는 `PASS`도 `REVIEW_REQUIRED`로 처리합니다. 이것은 인용의 존재·범위 검증이며 법적 해석의 정확성을 보증하지 않습니다.

## 바로 실행

```sh
# 원본으로 검색 인덱스 생성. 외부 API를 호출하지 않습니다.
npm run rag:index

# 원본·인덱스 동기화 확인
npm run rag:check

# 관련 법령 검색: 출처 ID, 조항, 원문, URL 출력
npm run rag:query -- "무료 제공 기간과 유료 전환 조건" GENERAL_ADVERTISING
npm run rag:query -- "식품의 질병 예방 치료 효능" GENERAL_FOOD

# 기존 데이터에 대한 검색 회귀 평가
npm run rag:eval
```

원본을 변경한 뒤 인덱스를 재생성합니다. 파일은 완성된 결과로 원자적으로 교체하며, 생성 실패 시 이전 파일을 보존합니다. 예전 `general-advertising.chunks.json`과 `general-food.chunks.json`은 과거 스냅샷이며 현재 앱은 `rag-index.json`을 읽습니다.

## OpenAI 임베딩 추가

로컬 `.env.local`에 다음을 설정합니다. 키를 소스 저장소나 브라우저 코드에 넣지 않습니다.

```dotenv
RAG_EMBEDDING_PROVIDER=openai
RAG_EMBEDDING_MODEL=text-embedding-3-small
RAG_EMBEDDING_DIMENSIONS=1536
OPENAI_API_KEY=발급받은_키
```

```sh
npm run rag:index -- --embed
npm run rag:query -- "무료 제공 조건" GENERAL_ADVERTISING
npm run dev
```

첫 실행은 모든 조항을 임베딩합니다. 다음 실행은 모델·차원·조항 해시가 같으면 기존 벡터를 재사용하며, 변경된 조항만 32개 이하 배치로 계산합니다. 모델이 바뀌면 전체를 다시 계산합니다. 입력은 항목당 UTF-8 8,000바이트로 제한하며 초과 시 본문을 자르지 않고 오류로 알립니다.

벡터 모드에서 검사하면 광고에서 만든 검색 질의가 선택한 임베딩 API로 전달됩니다. 법령 벡터는 검사 때 재생성하지 않습니다. 키와 네트워크가 없어 실제 외부 모델의 호출·품질은 이번 기본 구성에서 검증하지 않았습니다. 요청 형식과 응답 검증은 모의 HTTP 응답으로 테스트합니다. [OpenAI 임베딩 API](https://developers.openai.com/api/reference/resources/embeddings/methods/create)

## 로컬 Ollama 임베딩 추가

Ollama에 설치한 **임베딩 모델**의 정확한 모델명과 지원 차원을 설정합니다. 일반 대화 모델을 임베딩 모델로 사용하지 않습니다.

```dotenv
RAG_EMBEDDING_PROVIDER=ollama
RAG_EMBEDDING_MODEL=설치한_임베딩_모델명
RAG_EMBEDDING_DIMENSIONS=해당_모델의_출력_차원
RAG_OLLAMA_BASE_URL=http://127.0.0.1:11434
```

같은 `npm run rag:index -- --embed` 명령으로 생성합니다. 문서와 질의에 동일한 모델·차원을 사용합니다. API는 `/api/embed`를 사용하며 `truncate: false`로 본문이 조용히 잘리는 것을 막습니다. 모델별 검색용 프롬프트 접두사나 별도 질의 지침은 아직 적용하지 않으므로, 실제 한국어 평가 후 해당 모델에 맞는 제공자를 추가해야 합니다. [Ollama 임베딩 API](https://docs.ollama.com/api/embed)

배포된 Cloudflare Worker에서 `127.0.0.1`은 사용자 PC를 가리키지 않습니다. 로컬 Ollama는 앱도 로컬에서 실행할 때 사용하거나, 서버가 접근 가능한 인증된 HTTPS 서비스를 별도로 구성해야 합니다. 원격 서비스가 Bearer 인증을 받는다면 `RAG_OLLAMA_API_KEY`를 설정합니다. 모델 가중치를 바꾸는 경우 같은 태그를 재사용하지 말고 다른 모델 식별자로 전체 재생성합니다.

## 운영 및 한계

- `RAG_EMBEDDING_PROVIDER=none`으로 외부 호출 없이 BM25만 사용할 수 있습니다. 기존 벡터 인덱스를 일반 `rag:index`로 덮어쓰는 것은 막았습니다. 벡터 인덱스 갱신은 동일한 설정의 `--embed`를 사용합니다.
- 인덱스는 코드와 함께 보관되는 읽기 전용 데이터입니다. 별도 DB 비용이 없고 Cloudflare Worker에서 파일시스템이나 TCP 없이 읽습니다. 데이터가 커지면 저장소 인터페이스를 유지하며 PostgreSQL/pgvector의 HTTPS API로 교체할 수 있습니다. 스캔 이력 저장소는 이번 범위에 포함하지 않았습니다.
- 배포 시에는 생성한 인덱스와 **동일한** 모델·차원의 서버 환경변수를 설정해야 합니다. 로컬 `.env.local`은 배포 서버에 자동 복사되지 않으므로 운영 환경변수는 배포 플랫폼에 별도로 등록해야 합니다.
- 기존 데이터는 선별된 조항·요약을 포함하는 코퍼스입니다. 파일명의 `official`이나 인덱스 생성 성공이 최신 공식 전문·별표까지 검증했다는 뜻은 아닙니다. 원본을 새로 수집하거나 조문을 만들어 추가하지 않았습니다. 원본 URL과 확인일은 기존 값을 보존했습니다.
- 시행일은 오늘의 한국 날짜를 기준으로 미래 조항을 제외합니다. 과거 버전의 효력 종료일, 경과조치, 조항별 시행일, 정의·예외·별표의 자동 연결은 아직 구현하지 않았습니다.
- 기존 유사 행정사례 데이터는 기존 사례 검색 모듈이 담당합니다. 사례를 법령 본문과 섞어 같은 법적 효력으로 취급하지 않습니다.
- `evals/retrieval/cases.json`은 현재 코퍼스의 직접 질의·한국어 띄어쓰기·범위 밖 질의·시행일 필터를 확인하는 9개 회귀 사례입니다. 의미 검색 테스트는 합성 벡터로 알고리즘만 확인합니다. 실제 광고에 대한 검색 누락률이나 LLM 정확도를 의미하지 않습니다.
- 주장 추출과 최종 해석은 현재 제공자의 범위에 의존합니다. 이미지·비디오·유튜브 추출, 법령 자동 갱신, 생성형 LLM 연결은 후속 작업입니다.
