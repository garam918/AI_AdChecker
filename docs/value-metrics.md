# 평가 지표와 가치 검증

"기존 검수 30분 → ContentLint 30초" 같은 주장은 **측정값**과 **가정값**을 구분해서만 사용합니다. 이 문서는 무엇을 자동으로 측정하고, 무엇을 사람이 측정해야 하는지 정리합니다.

## 자동 측정 (모든 분석 결과에 포함)

`ScanAnalysisResult.metrics`

| 필드         | 의미                                                            |
| ------------ | --------------------------------------------------------------- |
| `elapsedMs`  | 요청 수신부터 결과 완성까지의 서버 소요 시간                    |
| `mode`       | `live`(AI 제공자 성공) 또는 `offline`(모든 AI 실패 → 규칙 기반) |
| `attempts[]` | 제공자·모델·소요 시간·성공/실패 코드. Vertex → OpenAI 순서      |

UI 결과 화면은 `Elapsed` 지표와 "이번 분석 N초 · 수동 사전검수 기준선 30분(가정) 대비 약 N배" 문구를 표시합니다. 기준선은 상수([content-lint-app.tsx](../src/features/scans/content-lint-app.tsx)의 `MANUAL_REVIEW_BASELINE_MINUTES`)이며 항상 "가정"으로 표기됩니다.

## 평가 데이터셋: `evals/end-to-end/cases.json` (40개)

| 구성                               | 개수   | 내용                                                                             |
| ---------------------------------- | ------ | -------------------------------------------------------------------------------- |
| 일반 광고 FLAG / SAFE              | 8 / 4  | 수치·우월성·비교·무료 조건 vs 중립 기능 설명                                     |
| 일반 식품 FLAG / SAFE              | 11 / 9 | 질병·기능성·의약품 오인·체험기·전후·전문가 vs 맛·원재료·영양정보·부정문·주의사항 |
| 건기식·의약품·의료기기·화장품 FLAG | 2×4    | 허가 범위·절대 안전성·전문가 보증·의약품 오인                                    |

`contextDependent: true`는 부정문·주의사항·체험기처럼 문맥이 결과를 결정하는 사례로, 별도 집계합니다.

### 지표 정의

- **탐지 성공률** = FLAG 사례 중 `expectedIssueTypes`가 모두 이슈로 나타난 비율.
- **출처 연결률** = 탐지된 FLAG 사례 중, 기대 유형과 일치하는 모든 이슈가 `citationStatus: VERIFIED`이고 저장된 조항 ID를 갖는 비율. 별도로 전체 이슈 중 검증 인용 비율도 보고합니다.
- **오탐률** = SAFE 사례 중 이슈가 1개 이상 발생한 비율. 오탐 사례 목록을 함께 출력합니다.
- **핵심 이슈 정리** = 결과당 평균/최대 이슈 수와 3개 이하로 정리된 비율.
- **지연 시간** = `elapsedMs` 평균·중앙값·p95.

### 실행

```sh
npm run eval:e2e                       # 규칙 + 규정 검색 (네트워크 없음, 회귀 기준)
npm run eval:e2e -- --live             # Vertex → OpenAI → 규칙 체인 (API 비용)
npm run eval:e2e -- --baseline-minutes=45 --strict
```

`outputs/compliance-evaluation.md`와 `.json`이 생성됩니다. `--strict`는 미탐·오탐·오류가 있으면 종료 코드 1을 반환합니다. 같은 데이터셋이 [compliance-evaluation.test.ts](../src/evaluation/compliance-evaluation.test.ts)에서 오프라인 회귀 하한(탐지 ≥ 90%, 출처 연결 100%, 오탐 0)으로 고정됩니다.

### 2026-09-14 오프라인 기준 결과

규칙 + BM25 검색만으로 40개 사례: 탐지 100% (27/27), 출처 연결 100% (27/27), 오탐 0% (0/13), 분류 정확도 100%, 결과당 최대 이슈 2개, 지연 중앙값 1ms 미만 (허가정보 조회가 붙는 규제 제품군은 0.5–1.9초).

이 숫자는 **이 데이터셋에 대한 회귀 측정**입니다. 데이터셋의 상당수가 규칙 설계에 쓰인 문구와 겹치므로, 실제 광고 모집단에 대한 탐지율로 해석하면 안 됩니다. `--live` 결과(AI가 추가로 추출하는 암시적 주장 포함)는 별도로 기록하고 사람이 출처 적합성과 수정안의 사실성을 검토해야 합니다.

## 사람이 측정해야 하는 것: 시간 절감 기준선

"30분"은 아직 가정입니다. 다음 절차로 실제 값을 얻은 뒤 상수를 갱신하세요.

1. 마케터·검수 담당 5명 이상에게 데이터셋에서 고른 광고 문구 6개(FLAG 4, SAFE 2)를 배정합니다.
2. **도구 없이** 관련 규정을 찾아 위험 표현·근거 조항·수정안을 적는 시간을 측정합니다 (시작~제출).
3. 같은 참가자가 다른 6개 문구를 **ContentLint 결과를 보고** 검토·수정하는 시간을 측정합니다. `metrics.elapsedMs`는 서버 시간이므로, 사용자가 결과를 읽고 조치를 결정하는 시간을 별도 스톱워치로 기록합니다.
4. 두 조건의 중앙값을 비교해 기준선(분)과 도구 사용 시간(초)을 문서와 UI 상수에 반영합니다. 표본 수, 참가자 경험 수준, 문구 난이도를 함께 기록합니다.
5. 정확도 검증 없이 시간 절감만 주장하지 않습니다. 참가자가 놓친 항목과 도구가 놓친 항목(미탐)을 같은 표에 기록합니다.

이 절차를 거치지 않은 수치는 자료·발표에서 반드시 "가정" 또는 "내부 벤치마크"로 표기합니다.
